# Rogue Knight Scaffold

元气骑士式俯视角 Roguelike 的**架构脚手架**：拆解原作公开可查的实现框架，从零搭一套结构对齐、能跑、能继续往下做的项目底子。

> **边界**：不含《元气骑士》的任何代码、素材、贴图或配置数值。所有精灵是运行时程序化绘制的占位图，所有配置表是演示用原创数值。原作是 Unity3D + C#，这里复刻的是**架构决策**，不是引擎也不是二进制。真去反编译商业 APK 拿到的也是混淆后的 IL，参考价值远低于公开的架构资料 + 一份干净的实现。

## 自动试玩

`scripts/bot-core.mjs` 是一个**不作弊**的机器人：只按 WASD / 鼠标 / E / 空格，读公开状态，用真实的 `Game.update` 推进。它回答的不是「会不会崩」，而是「好不好玩」——死在哪层、被什么打死、一层多久、能量够不够、商店买得起吗、会不会卡住。

最近一次结果见 **[docs/PLAYTEST_REPORT.md](docs/PLAYTEST_REPORT.md)**（30 局，含已修问题、难度曲线、伤害来源、经济与优先级建议）。

## 平衡机制（P0~P3）

后期难度、资源经济、天赋与武器分布都由**机制**控制，而不是继续堆数值：

| 维度 | 机制 | 关键文件 |
|---|---|---|
| 后期难度 | **精英词条**：L6 起按层概率带护盾/迅捷/重甲/爆裂，L14 起可双词条；**多波次**：L10 起 2 波、L18 起 3 波；**BOSS 狂暴**：半血进入二阶段 | `data/affixes.ts` / `world/Room.ts` / `entities/Enemy.ts` |
| 资源经济 | 金币掉落收敛 + 商店**按层复合定价**（L30 约 5.4 倍）；能量池收紧 + 补给球产出砍 76% | `data/shop.ts` / `data/characters.ts` |
| 天赋分布 | 同 stat **递减叠加**（`0.82^stacks`，给成长加天花板）+ 候选**跨类轮询** | `data/talents.ts` / `state/RunState.ts` |
| 武器跨度 | 评分纳入机制/射程/能量可持续性，弱武器补机制、强武器回收 | `data/weapons.ts` / `scripts/bot-core.mjs` |


## 操作

### 开始界面

打开页面先进入**主菜单**（背景是真实生成的关卡），四个入口：

| 选项 | 说明 |
|---|---|
| 1 开始游戏 | 新开一局 |
| 2 图鉴 | 浏览 24 把武器 / 14 种敌人 / 27 条天赋：左侧列表（↑↓ 或滚轮翻，右侧显示数值、机制、攻击方式详情），1/2/3 或 ←→ 切页 |
| 3 设置 | 镜头跟随速度（缓慢/标准/迅捷）、屏幕震动、鼠标准星、小地图，全部**立即生效并写入存档**；恢复默认一键还原 |
| 4 操作说明 | 键位一览 |

键盘 `↑↓ / W S` 选择、`Enter` 确认、数字键直达，也可以直接点鼠标；`Esc` 从图鉴 / 操作说明返回主菜单。

**局内也能改设置**：游戏中按 `P` 或 `Esc` 打开**暂停菜单**（继续游戏 / 设置 / 返回主菜单），选「设置」进入和主菜单同一份设置页，改动立即生效、写回存档，按 `Esc` 返回暂停菜单、**本局进度完整保留**（不会重建关卡、不丢血量 / 武器 / 层 / 计时）。只有显式选「返回主菜单」才放弃本局（金币**不结算**成宝石，防止刷宝石）。死亡界面按 `Esc` 仍直接回主菜单。

### 游戏内

| 键 | 动作 |
|---|---|
| WASD / 方向键 | 八向移动 |
| 鼠标 | 独立瞄准（**不会被移动方向覆盖**） |
| 左键（按住） | 连发 |
| Space / Shift | 翻滚，带无敌帧 |
| Q / Tab | 切换两把武器 |
| E | 拾取武器 / 开宝箱 / 进传送门 / 与商人对话 / 领取神龛（**一次只消费一个目标**）|
| 1 ~ 4 | 天赋面板四选一（也可点击卡片） |
| 1 ~ 4 | 商店面板购买对应商品（也可点击卡片） |
| E / Esc / P | 关闭商店面板 |
| P / Esc | **暂停菜单**：继续 / 设置 / 返回主菜单（再按一次继续本局） |
| R | 重开一局 |
| F3 | 调试浮层（种子、池用量、计时、天赋、生成器自检） |
| F9 | 换种子重建本层 |

一局流程：出生房 → 清战斗房开门 → **商店房**花金币补给 / **奖励房**白拿 → 宝箱房换枪 → BOSS 房 → 传送门进下一层（**每层结束都弹一次天赋四选一**）→ 死亡结算永久宝石。

右上角小地图左侧实时显示**本层用时 / 总用时 / 历史最快单层 / 已获天赋数**；面板与暂停期间计时冻结。

镜头会**缓慢跟随角色**：房间比视口高，走近任意一侧的门时镜头才跟过去，门与角色始终留在画面里；同时把视口钳制在房间边界内，不会露出大片空背景。手感参数在 `data/balance.ts` 的 `cameraLerp`（越小越慢）与 `cameraEdgeMargin`。

**交互优先级**：武器 / 宝箱 > 神龛 / 商人 > 传送门。BOSS 掉的武器常落在房间中心的传送门旁边，早期只按距离选目标，想捡枪却会被传走。现在仲裁用 `距离² × 权重` 打分（`balance.ts` 的 `interactBias`），传送门权重最大（不可逆操作），BOSS 掉落也会被推离中心至少 3 格。两者距离接近时一定先拿到武器，捡完再按 E 才进下一层。

**换枪不丢枪**：最多带两把武器，武器栏满时捡 / 开箱 / 商店买枪会顶替**当前手持**，被顶替的那把会掉回地面（走 `safeSpawn` 校验不嵌墙），可以走回去按 E 捡回，不再凭空消失。刚落地的枪有 0.6s 交互保护期（`balance.ts` 的 `weaponDropGrace`）：期间既不响应 E、也不参与交互仲裁，避免连按 E 时「捡 A → 掉 B → 又捡 B → 掉 A」无限对换，也不会抢占你想进的传送门。三个换枪来源统一走 `GameCtx.giveWeapon()` 这一个入口。

## 武器品质

24 把武器分 5 档，**名字颜色 = 品质**，没有第二处硬编码色值：

| 品质 | 颜色 | 解锁层 | 武器数 | 典型武器 |
|---|---|---|---|---|
| 普通 | 灰白 `#c8cdd8` | 1 | 3 | 破旧的手枪 / 锈铁短剑 / 猎弓 |
| 精良 | 绿 `#7fd48a` | 1 | 6 | 霰弹枪 / 冲锋枪 / 光剑 / 三连发手枪 / 苦无 / 十字弩 |
| 稀有 | 蓝 `#6fb8ff` | 2 | 6 | 轨道炮 / 榴弹发射器 / 弹射短弓 / 火焰喷射器 / 武士刀 / 追踪飞镖 |
| 史诗 | 紫 `#c9a0ff` | 4 | 5 | 等离子步枪 / 火箭筒 / 加特林 / 风暴之弓 / 虚空之刃 |
| 传说 | 橙 `#ffb347` | 6 | 4 | 奇点炮 / 圣剑 / 龙息 / 磁暴狙击炮 |

品质只决定**掉落概率与配色**，不直接决定强度 —— 数值逐把调，避免「高品一定全面更强」把品质退化成等级。掉落权重随层数上升（普通衰减、稀有上升），但 `minLevel` 门槛保证 1 层开不出传说。

武器机制不是换皮，`WeaponData` 有 6 个可选字段，由同一套开火 / 子弹逻辑实现：

| 机制 | 字段 | 示例 |
|---|---|---|
| 连发 | `burst` / `burstGap` | 三连发手枪（能量按三发预扣） |
| 弹墙 | `bounce` | 弹射短弓、风暴之弓 |
| 爆炸 | `explode` / `explodeDamage` | 榴弹发射器、火箭筒、奇点炮 |
| 追踪 | `homing` | 追踪飞镖、奇点炮 |
| 吸血 | `lifesteal` | 武士刀、虚空之刃、圣剑 |
| 宽扇形 | `arc` | 圣剑接近半圆，短剑只有窄扇 |

## 敌人与攻击

敌人 = 走位 AI + 攻击配置。攻击声明前摇 / 伤害 / 弹数 / 爆炸 / 激光 / 召唤，`Enemy` 只推 `windup → execute → recover` 三段状态，不再堆 `if`。

| 敌人 | 走位 | 攻击 | 出现层 |
|---|---|---|---|
| 哥布林 / 洞穴蝙蝠 | 贴脸 | 近战 | 1 |
| 野猪 | 蓄力冲撞 | 冲刺撞击 | 2 |
| 哥布林祭祀 | 保持中距 | 单发弹 | 2 |
| 投弹哥布林 | 保持中距 | 榴弹（引信 1.5s，半径 30） | 3 |
| 分裂史莱姆 | 贴脸 | 近战，死亡分裂成 2 只小史莱姆 | 3 |
| 邪眼 | 绕圈 | 三发扇形 | 4 |
| 哥布林弩手 | 保持远距 | 高伤慢弹（前摇 0.7s） | 4 |
| 石像鬼 | 原地 | **激光**（0.75s 预警线 → 0.3s 光束，墙会挡光） | 5 |
| 亡灵召唤者 | 保持距离 | **召唤**蝙蝠 + 紫弹 | 6 |
| 关卡守卫 | 保持中距 | 5/7 发扇形 + 榴弹 | BOSS 1-2 层 |
| 熔岩巨像 | 保持中距 | 激光 + 9 发环形 | BOSS 3-4 层 |
| 死灵君王 | 保持中距 | 召唤 3 只蝙蝠 + 扇形 + 重弹 | BOSS 5-6 层 |

BOSS 每两层换一个，三套轮换后循环。所有攻击**前摇 > 0**（回归脚本强制），没有无法躲避的伤害；激光前摇额外要求 ≥ 0.5s。

## 自检

脚手架内置四道守卫，改生成器后能立刻发现问题：

- `TemplateLibrary.validateAll()` — 每个模板的「外圈留空 / 内部连通」
- `validatePlan(plan)` — 门成对、门连正交相邻格、全房间可达、门图是树、**保证房恰好各一个**、`requiredBattles` 与实际战斗房一致
- F3 浮层 — 把上面两项结果、池用量、计时、天赋、商店库存、当前武器品质直接显示出来
- **`npm run verify`** — 常驻回归，一次跑完十二组：
  - 生成器：200 种子 × 12 层 + 3 组极端参数 = 2880 关
  - 交互仲裁 8 项（含 3 项优先级权重）
  - 相机跟随 5 项（255 采样点）
  - 天赋 6 项（抽取策略 / 27 条逐条生效 / stat 消费者 / 面板布局）
  - 武器与品质 7 项（24 把配置自洽 / 5 档配色不重复 / 1 层不出史诗 / 深层出传说 / minRarity 降级 / 掉落池合法）

商店 / 奖励房是**结构性保证**而非概率：先一次性收集全部合法空位公平分配，空位耗尽时降级「就地改类型」补上（树形门图不变），末尾还有 fail-fast 断言。

天赋每层结束后四选一，抽取**优先给本局没拿过的**（27 条池子前 6 层不重复）。回归会把 27 条逐条应用到全新 `RunState`，断言至少改变一个字段 —— 同时抓住「声明了 stat 却没接 case」和「字段被赋值但没人读」两类摆设参数。

镜头跟随同样是**结构性保证**：`cameraTarget()` 是纯函数，分轴把视口钳制在房间内 —— 房间比视口高的轴跟着玩家走、比视口窄的轴锁中心，所以玩家走到任意门口时该门都在视口内，且不会把房间外的空背景带进画面。跟随速度可在设置页调整（缓慢 / 标准 / 迅捷，写入存档）。

精灵覆盖也进了回归：`SpriteAtlas.SPRITE_IDS` 是唯一清单，`sprite()` 找不到 id 只会画洋红圆、不会报错，所以用静态断言把「加了新怪忘画贴图」变成非零退出码。

开始界面的菜单 / 设置 / 图鉴沿用天赋面板当年的教训：**布局常量与命中检测一起导出**（`menuItemRect` / `hitMenuItem` 等），绘制端和输入端引用同一份坐标，不会出现「看得见点不到」。设置项存的是选项下标，读档统一 `normalizeSettings()` 钳制 —— 老档缺字段、手改 localStorage 越界都只会退回默认，不会把 NaN 传到渲染层。

控制台里 `__game` 可以直接看 `__game.level.plan`、`__game.run`、`__game.room`；调试时可手动 `__game.openShop()` / `__game.grantTalent()`。
