# 自动试玩报告

> 用「不作弊的机器人」把游戏真的跑起来打一遍，找出体验、平衡、流程上的问题。
> 数据：`docs/playtest-data.json`（30 局原始记录）｜复现：`node scripts/playtest.mjs --runs 30 --max-levels 30`

---

## 0. 一句话结论

**流程能从头玩到尾；上一轮定位的 P0~P3 四个结构性失衡已全部落地，并用同一套自动试玩复测：后期不再倒挂、BOSS 房伤害占比回到 31%、天赋不再被四件套锁死、武器跨度从 10 倍压到 3 倍出头。剩一个硬骨头——「能量」在自动回能框架下仍偏宽松，需要重构而不是调数值。**

## 1. 怎么跑的

### 机器人设计

`scripts/bot-core.mjs`，约束是**只用玩家能用的东西**：

| 允许 | 禁止 |
| --- | --- |
| 往 `Input` 里按 W/A/S/D、鼠标、E、Space | 直接改 `run.hp` / `enemy.hp` |
| 读 `game` 的公开状态（位置、房间、敌人、掉落） | 调内部私有方法跳过战斗 |
| 用 `Game.update(dt)` 推进 | 加速时间或改 `dt` |

行为循环：清房间 → 捡东西 → 选下一间 → 打。战斗里按射程保持距离、绕柱走 BFS 路径、来弹翻滚；清房后依次处理武器/宝箱/神龛/商店/传送门。

### 口径

- 一局 = 一个种子，从第 1 层打到第 30 层或死亡；
- 单层上限 240 秒游戏时间（超时记为「未通过」，不记死亡）；
- 输出：每层用时/击杀/受伤/层末血量、伤害来源、按房间伤害、能量水位、商店经济、精英/多波次遭遇、天赋与武器分布、卡点现场。

### 这一轮先把「测量工具」修了

上一版报告里 11 次层超时中有 9 次是**机器人在已清空的房间里追金币绕不出来**（`roomState=cleared / enemies=[] / goal:coin`），属于工具缺陷、会污染「平均到达层」等指标。本轮根治：

- **金币目标锁定**：认准一颗追到手/放弃才换，不再每帧 `find()` 漂移导致放弃计时永远归零；
- **房间级金币预算（5 秒）**：本房追金币累计超预算就直接走门，与战斗时长解耦；
- 超时现场新增 `waveCount / eliteCount / coinChaseT` 诊断字段。

修完后 30 局只剩 **1 次**层超时（见 §6.3），且接管开火测试能打出伤害，确认不是游戏卡关。

## 3. 上一轮修掉的问题（保留记录）

### 3.1 致命：BOSS 生成在墙里（43.7%）

机器人反复卡在 BOSS 房，剩余敌人永远是一条 `boss hp84` 不动 —— 不是打不动，是打不到。1200 关压测 `bossSolid: 524`（43.7%）。

**根因**：BOSS 固定生成在「房间中心上方两格」，那里经常是柱子。第一版修法只吸附到「格子可走」，仍 43.7% —— 因为 BOSS 半径 13~14，**比一格（16px）还宽**，格子可走 ≠ 身体放得下。

**修法**：`Room.safeSpawn(prefer, radius)` 逐格验证 `collides(x, y, radius)`，BOSS / 普通怪 / 商人 / 宝箱 / 传送门 / 掉落全部改走安全点。验证：1200 关 `bossSolid: 0`。

### 3.2 高：贴脸开火打空

野猪与玩家重叠（相距 1.4px），磁暴炮连打 2 发伤害 0。根因：子弹第一步位移跨过目标中心。**修法**：`Projectile` 出生帧先结算一次命中。新增常驻测试覆盖磁暴炮/火焰/手枪/武士刀。

### 3.3 高：高射速武器能耗黑洞

龙息 48/s、火焰 35/s、加特林 29/s，回能仅 9/s —— 按住扳机龙息只能输出 19% 时间，而开局手枪能量效率是传说的 2.4 倍。**修法**：压单发能耗（火焰 2.2→1.2、加特林 1.7→1.1、龙息 2.4→1.5、奇点炮 20→14）。饥饿率 40.7% → 0.7%。

### 3.4 高：敌人不随层数成长

代码里没有任何等级缩放，30 局 0 死亡，每层受伤 L6 峰值 15.3 → L30 只有 3.0。**修法**：`Enemy.applyLevelScale()`（血 +10%/层、伤 +5%/层）。本轮补上遗漏：**远程弹幕此前没乘 `powerScale`**，导致会放弹的怪到后期等于没成长，已修正。

## 4. P0~P3 优化：做了什么

### 4.1 P0 后期偏软 —— 用机制而不是数值

原诊断：玩家成长无上限（天赋每层叠 + 品质武器 + 血 7→19），敌人只有血/伤两维。继续堆数值只会把前期也变硬。改为三件机制：

| 机制 | 实现 | 为什么能治后期 |
| --- | --- | --- |
| **精英词条** | L6 起每只怪按层概率带词条（护盾/迅捷/重甲/爆裂），L14 起可双词条 | 改变交战方式：护盾拖 TTK、重甲逼换高伤枪、爆裂惩罚贴脸清场 |
| **多波次** | 战斗房 L10 起 2 波、L18 起 3 波，清空当前波才放下一波、门保持锁 | 打断「一波 AOE 全清 + 站着回血」，压力持续 |
| **BOSS 狂暴** | BOSS 血量过半进入狂暴：攻速 ×0.7 间隔、移速 ×1.2，并震屏+粒子提示 | 给 BOSS 战一个「阶段转换」节点，后半段更危险 |

配套：BOSS 从 L12 起至少带 1 条词条、深层 BOSS 房分两波（BOSS+护卫 → 精英援军）。

### 4.2 P1 资源空转 —— 金币收紧 + 能量重定性

- **金币**：产出下调（击杀掉币 0.75→0.5）+ 清房掉落收敛 + 商店定价按层复合增长（`price × 1.06^(层-1)`，L30 约 5.4 倍）。每层金币 352 → **195**。
- **能量**：见 §6.2 —— 这一条只做了一半，且发现旧指标（饥饿率）根本照不出问题。

### 4.3 P2 天赋去同质化 —— 递减 + 跨类

- **同 stat 递减**：`talentDecay(stacks) = 0.82^stacks`，同类叠加边际收益递减（连拿 30 次伤害天赋，倍率收敛到 7.47，而不是 1.4^30 的指数爆炸）。这同时给「玩家成长无上限」加了天花板，反向缓解 P0。
- **候选跨类轮询**：一次 4 张候选按 tag 轮询（生存/输出/能量/机动/资源各出），不再四张全是输出。
- **机器人评分感知递减**：`talentScore` 乘 `talentDecay`，理性代理会自然转向没叠过的维度。

### 4.4 P3 武器跨度 + BOSS 房存在感

- **评分口径修正**：旧 `weaponScore` 近战无条件 ×1.3 且不扣能量，导致前 6 名 5 把近战、破锈短剑碾压磁暴炮；bounce/homing/lifesteal/arc 等机制完全不计分。重写后：爆炸按 AOE DPS 估、机制进分、射程可达性折减、能量可持续性按回能 9.5 对齐。
- **弱势补强**：弹射短弓 / 榴弹 / 火箭 / 磁暴 / 冲锋枪 / 猎弓 上调机制或数值；圣剑 18→13、虚空之刃 12→10 回收过强项。
- **跨度**：52.4/5.1 = 10.3x → **3.3x**。

## 6. 剩余问题与后续议题

### 6.1 P1 金币：已收敛，但「花不完」只解了一半

每层金币 352 → 195，金币价值确实提升了（定价涨到 L30 约 5.4 倍）。但购买次数 4.6 → 4.7 基本没变 —— 说明**收入降下来的同时定价也涨上去了，净效果是「同样的钱买更少的东西」**，而「一局到底能花几次」的结构没变。

后续方向：给金币加一个**不止于商店的出口**（例如局内赌徒/重铸武器词条/永久货币转换），让它从「买东西」变成「做选择的筹码」。

### 6.2 P1 能量：只收敛了收入端，还没成为强约束

**先纠正一个上一轮的误判**：上一版把回能 11→9.5 想让「饥饿率回升」，结果饥饿率反而归零，当时以为是指标坏了。8 局加指标实测后真相是：

- 饥饿率只统计「连一发单发成本都扣不起」的帧。能量池 200、单发能耗 1~18、回能 9.5/s —— 只要池子里有 18 点就永远能开火，所以这个指标在**结构上就测不到「能量是否影响决策」**。
- 真正该看的是**能量水位**：实测战斗中能量条均值 **97.6% 满**、一局捡 **448 个能量球**。能量根本不是资源，是背景。

本轮已做的（真实、可验证）：

1. **能量池收紧** 200/180/260 → **110/100/145**（-45%），让「上限类天赋」重新有价值；
2. **补给球产出砍 76%**：击杀掉球 0.24→0.13、清房从「必掉」改 40% 概率、奖励房面额 14→10；
3. **修一致性缺陷**：`Pickup` 里 heal/armor 都有「满状态不吸附」，唯独 `energy` 满蓝也把球吸走白费 —— 已对齐；
4. **指标换血**：playtest 新增 `avgEnergyRatio / lowWaterRate / emptyRate / energyPickups`，以后看水位不看饥饿率。

**结果**：能量球/层 21.6 → 5.2，低水位帧 0.1% → 0.8%，饥饿率仍 0.2%（没熄火）。但水位仍 96.7% —— **收入端收敛了，能量还没成为「泼水 vs 留蓝」的强决策**。

**为什么不再硬调**：回能 9.5 是「空蓝后 1 秒攒够一发」的保底，再压就回到上一轮修过的「40% 帧熄火 + BOSS 房超时」。要真正让能量紧张，需要的是**框架级改动**，而不是继续拧数值：

- 取消/大幅削弱自动回能，改由**能量球 + 击杀回能**供给（能量变成需要主动管理的弹药）；
- 或把能量定位成**技能/大招资源**（攒满放一次爆发），而不是「子弹费」。

这两条都超出「优化一下」的范围，作为独立议题留下。

### 6.3 唯一一次层超时（1/30）

```
L15  combat  roomState=fighting  waveCount=2  eliteCount=2
剩余敌人：slime hp25，可命中格 86
机器人目标：door:e->1（在追门，没打那只残血 slime）
接管开火测试：30 发打出 5.4 伤害 → 游戏侧命中/伤害正常
```

多波次房里机器人与「第二波刚生成 + 房间切换时序」撞了一下，卡在追门。**游戏侧可命中、接管测试能打出伤害**，属于机器人导航偶发，不是游戏卡关。1/30 的影响可忽略，但已在报告留档，避免下次误判为游戏 bug。

### 6.4 测量工具仍需注意

- 「卡住」计数（13974）包含「走向门时短暂减速」，是噪音指标；真实层超时已降到 1，不必据此判断游戏卡关；
- 机器人不会用位移技能、不会卡视野拉扯，绝对难度结论要打折看；
- 30 局死亡数仍有随机波动（0~4），难度判断看「每层平均受伤曲线」，不看单次死亡率。
